GitHub توسّع مؤشرات Copilot CLI لتشمل تخصيصات الوكلاء

أعلنت GitHub توسيع تغطية تقارير استخدام Copilot CLI بإضافة مؤشرات لنشاط التخصيصات الوكيلة. وتتيح البيانات الجديدة لمسؤولي المؤسسات والمنظمات معرفة الأدوات الأكثر استخدامًا واتساع تنوعها.

نُشر: 18 سبتمبر 2026
آخر تحديث: 18 سبتمبر 2026 · 4 دقائق قراءة

الخلاصة

  • المؤشرات الجديدة تغطي المهارات والوكلاء المخصصين وخوادم MCP والأوامر المائلة والإضافات.
  • تظهر البيانات في تقارير يومية وفترات 28 يومًا، سواء على مستوى المستخدم أو بصورة إجمالية.
  • تسرد التقارير ما يصل إلى خمسة عناصر ذات أعلى نشاط، إلى جانب عدد العناصر المختلفة المستخدمة.
  • لا تعرض التقارير أسماء التخصيصات التي يعرّفها العملاء، وتجمعها ضمن تصنيفات تحمي الخصوصية.
  • تتوفر البيانات للمخولين بعرض مؤشرات Copilot مع تفعيل سياسة مؤشرات الاستخدام.

توسيع نطاق تقارير Copilot CLI

أضافت GitHub إلى واجهة برمجة تطبيقات مؤشرات استخدام Copilot تغطية جديدة للنشاط المرتبط بتخصيصات Copilot CLI ذات الطابع الوكيلي. وتشمل الإضافة المهارات، والوكلاء المخصصين، وخوادم Model Context Protocol المعروفة اختصارًا بـ MCP، والأوامر المائلة، والإضافات. وتأتي هذه الخطوة امتدادًا لتقارير CLI الموجودة، بدل أن تكون نظام تقارير منفصلًا.

تظهر الحقول في تقارير المؤسسات والمنظمات اليومية لمدة يوم واحد، سواء في التقارير الفردية لكل مستخدم أو التقارير الإجمالية. كما تتوفر في تقارير المستخدمين الممتدة 28 يومًا، وفي إدخالات day_totals ضمن التقارير الإجمالية للفترة نفسها. وبذلك يمكن قراءة النشاط على مستوى مستخدم بعينه أو جمعه عبر المؤسسة أو المنظمة.

ما العناصر الأكثر استخدامًا؟

تجيب مصفوفات totals_by_skill وtotals_by_custom_agent وtotals_by_mcp وtotals_by_slash_cmd وtotals_by_plugin عن سؤال رئيسي: ما التخصيصات التي تسجل أكبر قدر من النشاط؟ وتعرض كل مصفوفة ما يصل إلى خمسة عناصر ذات أعلى نشاط مسجل، مع قيمة interaction_count لكل عنصر.

يختلف معنى هذا العدد بحسب الفئة. فهو يحصي مرات استدعاء المهارات والأوامر المائلة ومهارات الإضافات، كما يحصي مرات بدء الوكلاء المخصصين ومحاولات الاتصال بخوادم MCP. ولا يعني عدد خادم MCP عدد مرات استخدام الأدوات بعد نجاح الاتصال؛ إذ يرتفع العداد عندما يحاول Copilot CLI الاتصال بالخادم أو إعادة الاتصال به، سواء نجحت المحاولة أو فشلت.

أما استدعاء الأدوات عدة مرات من خادم متصل بالجلسة نفسها فلا يزيد interaction_count. وتساعد هذه القاعدة على فصل نشاط الاتصال بالخادم عن كثافة استخدام أدواته.

قياس تنوع التخصيصات بمرور الوقت

تتضمن التقارير كذلك حقولًا لعدد العناصر المختلفة المستخدمة: distinct_skill_use_count وdistinct_custom_agent_use_count وdistinct_mcp_use_count وdistinct_slash_cmd_use_count وdistinct_plugin_use_count. وفي التقرير الفردي يُحتسب كل عنصر استخدمه ذلك المستخدم مرة واحدة، بصرف النظر عن عدد مرات تشغيله.

في المقابل، يحصي التقرير الإجمالي كل عنصر استخدمه أي شخص داخل المؤسسة أو المنظمة مرة واحدة، وليس مرة لكل مستخدم. وتشمل هذه الأعداد العناصر التي لا تظهر في قائمة الخمسة الأوائل، ما يجعل مقارنتها عبر الزمن وسيلة لقياس ما إذا كان نطاق التخصيصات المستخدمة يتسع أو يضيق.

وتوضح GitHub أن مؤشرات الإضافات تمثل مجموعة فرعية من مؤشرات المهارات، لأنها تحصي فقط استدعاءات المهارات المرتبطة بإضافة. لذلك يظهر تفاعل الإضافة أيضًا ضمن إجمالي المهارات، بينما لا تظهر المهارات غير المرتبطة بإضافات ضمن إجمالي الإضافات، ولا ينبغي جمع العددين معًا.

الخصوصية وتصنيف الأسماء

تعرض التقارير أسماء العناصر التي توفرها GitHub، لكنها لا تعرض أسماء التخصيصات التي يعرّفها العملاء، بهدف حماية الخصوصية. وتُجمع المهارات والوكلاء المخصصون وخوادم MCP والإضافات التي أنشأها العملاء تحت تصنيف other. أما الأوامر المائلة التي يعرّفها العملاء، فتستخدم لها تقارير Copilot CLI تصنيف custom، وهو التصنيف المعتمد أصلًا لهذا النوع من القياس.

وتشير المصفوفات الفارغة والقيم الصفرية إلى عدم تسجيل نشاط مطابق للفئة أو الفترة المطلوبة. أما ظهور الحقول بقيمة null أو غيابها، فيعني أن بيانات التخصيص غير متاحة. ويساعد هذا الفرق في التمييز بين غياب النشاط وتغيب البيانات نفسها عند تحليل التقارير.

صلاحيات الوصول وما الذي تستفيده الفرق

تقول GitHub إن ملاك المؤسسات ومديري الفوترة، وملاك المنظمات، وأصحاب الأدوار المخصصة التي تمنح صلاحية View Copilot Metrics، سيتمكنون من الوصول إلى هذه التقارير، على أن تكون سياسة مؤشرات استخدام Copilot مفعّلة. ولا تمنح إضافة الحقول وصولًا عامًا؛ إذ يظل الاطلاع مرتبطًا بالصلاحيات وإعدادات السياسة المعتمدة.

تتيح البيانات الجديدة للمسؤولين رصد التخصيصات التي تكتسب انتشارًا، واكتشاف جوانب نقص التمكين أو التدريب، وتحديد الأتمتة التي يجدها المطورون ذات قيمة. ويظل هذا الاستخدام وصفًا لنشاط مسجل في التقارير، لا حكمًا مستقلًا على جودة كل أداة أو فاعليتها التقنية.
