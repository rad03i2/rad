GitHub Copilot يدعم OpenTelemetry لمراقبة أداء الوكلاء

أصبح بإمكان مسؤولي المؤسسات الآن تفعيل إطار OpenTelemetry في تطبيق GitHub Copilot لمراقبة نشاط الوكلاء الذكيين وتحليل تفاعلاتهم مع النماذج اللغوية والأدوات البرمجية.

نُشر: 23 سبتمبر 2026
آخر تحديث: 23 سبتمبر 2026 · 4 دقائق قراءة

الخلاصة

  • دعم جديد لإطار OpenTelemetry (OTel) في تطبيق GitHub Copilot عبر إعدادات إدارة المؤسسات.
  • إمكانية تحليل جلسات الوكلاء وتتبع الطلبات المرسلة إلى نماذج الذكاء الاصطناعي والأدوات المستخدمة.
  • تتبع خطوات التنفيذ خطوة بخطوة لاستكشاف السلوك غير المتوقع داخل أدوات المراقبة الحالية.
  • إدارة مركزية لسياسات المراقبة عبر الفرق دون الحاجة إلى إعدادات فردية لكل مطور.
  • استبعاد محتوى الأوامر والاستجابات بشكل افتراضي لضمان الخصوصية، مع إمكانية التفعيل عبر سياسات محددة.

إدماج إطار المراقبة المفتوح المصدر

أعلنت شركة GitHub عن إضافة دعم رسمي لإطار OpenTelemetry (OTel) في تطبيق GitHub Copilot، وهو إطار عمل مفتوح المصدر مصمم لمراقبة الأداء والقياسات في الأنظمة الموزعة. يأتي هذا التحديث ليمنح مسؤولي المؤسسات أدوات دقيقة لفهم كيفية أداء وكلاء Copilot الذكيين وتفاعلاتهم مع نماذج الذكاء الاصطناعي والأدوات البرمجية المختلفة. من خلال هذا التكامل، يمكن للمؤسسات إرسال بيانات نشاط الوكلاء مباشرة إلى أدوات المراقبة المتوافقة مع بنية OTel الخاصة بها، مما يوفر رؤية شاملة للعمليات التقنية دون الحاجة إلى حلول مغلقة أو مخصصة. ويمكن الرجوع إلى GitHub Changelog للاطلاع على التفاصيل الأصلية للمصدر.

تحليل جلسات الوكلاء وتتبع التفاعلات

يوفر هذا التحديث ميزة أساسية تتمثل في القدرة على تحليل جلسات الوكلاء (Agent Sessions) بشكل مفصل. يمكن للمطورين والمهندسين الآن تتبع تدفق الجلسة بالكامل، بدءًا من الطلبات المرسلة إلى نماذج الذكاء الاصطناعي، مرورًا بالأدوات التي يستخدمها الوكيل لتنفيذ المهام، وصولاً إلى النتائج النهائية. هذا المستوى من التفصيل يساعد الفرق الهندسية على فهم آلية اتخاذ القرارات داخل الوكيل، وتحديد أي نقاط قد تكون غير فعالة أو تستهلك موارد زائدة. كما يتيح النظام مراجعة مسارات التنفيذ خطوة بخطوة (Step-by-step traces) داخل أدوات المراقبة القائمة لدى المؤسسة، مما يسهل استكشاف السلوك غير المتوقع أو الأخطاء التي قد تحدث أثناء تنفيذ المهام المعقدة. ويمكن الرجوع إلى Back to changelog للاطلاع على التفاصيل الأصلية للمصدر.

الإدارة المركزية لسياسات المراقبة

من أبرز مزايا هذا التحديث هو الانتقال من الإعدادات الفردية إلى الإدارة المركزية. بدلاً من مطالبة كل مطور بإعداد أدوات المراقبة بشكل مستقل، يمكن للمسؤولين تطبيق إعدادات التلبيمة (Telemetry) على مستوى المؤسسة بأكملها أو على فرق محددة. يتم ذلك من خلال ملف managed-settings.json الخاص بالمؤسسة، حيث يمكن تحديد نقطة النهاية (Endpoint) التي ستستقبل بيانات المراقبة. هذا النهج يضمن اتساق سياسات المراقبة عبر جميع الفرق، ويقلل من العبء الإداري على المطورين، مع تعزيز الامتثال للمعايير الأمنية والتقنية المعتمدة داخل المنظمة. كما يسهل هذا التكامل دمج بيانات Copilot مع أنظمة المراقبة الحالية التي تستخدمها فرق العمليات (DevOps) والهندسة.

الخصوصية واستبعاد المحتوى الحساس

تولي GitHub أهمية كبيرة لخصوصية البيانات، ولذلك يتم استبعاد محتوى الأوامر (Prompts) والاستجابات (Responses) بشكل افتراضي من بيانات المراقبة التي يتم إرسالها عبر OpenTelemetry. هذا الإجراء يضمن عدم تسرب المعلومات الحساسة أو الكود الخاص بالمستخدمين إلى خوادم المراقبة الخارجية دون إذن صريح. ومع ذلك، توفر المنصة إمكانية تعديل هذه الإعدادات عبر سياسات التقاط المحتوى (Content-capture settings) إذا رأت المؤسسة حاجة ماسة إلى تحليل المحتوى لأغراض محددة. يُنصح المسؤولون بمراجعة هذه الإعدادات بعناية قبل تفعيل أي خيارات إضافية، للتأكد من توافقها مع سياسات الخصوصية والأمان المعتمدة داخل مؤسستهم.

القيمة المضافة للمؤسسات التقنية

يمثل هذا التحديث خطوة مهمة نحو نضج أدوات الذكاء الاصطناعي في بيئات المؤسسات. من خلال توفير رؤية شفافة حول أداء الوكلاء، يمكن للشركات تحسين استخدام موارد الحوسبة السحابية، وتقليل تكاليف الاستدعاءات غير الضرورية للنماذج، وتحسين جودة النتائج النهائية. كما يساعد هذا التكامل في بناء ثقافة هندسية تعتمد على البيانات (Data-driven) لتحسين عمليات التطوير. مع تزايد اعتماد الشركات على وكلاء الذكاء الاصطناعي لأتمتة المهام البرمجية، تصبح مراقبة الأداء والاستقرار أمراً حيوياً لضمان موثوقية هذه الأدوات في بيئات الإنتاج الحرجة.
