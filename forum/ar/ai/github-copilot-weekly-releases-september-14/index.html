GitHub Copilot يوسّع اختيار النماذج ومراجعة الشيفرة

كشفت GitHub عن مجموعة تحديثات جديدة في إصدارات Copilot الأسبوعية، مع تحسينات تمتد من اختيار النماذج ومراجعة الشيفرة إلى أدوات الوكلاء والإدارة.

نُشر: 19 سبتمبر 2026
آخر تحديث: 19 سبتمبر 2026 · 4 دقائق قراءة

الخلاصة

  • إضافة ثلاث درجات لاختيار النموذج تلقائياً وفق الكلفة والجودة وسرعة الاستجابة.
  • تحسين مراجعة الشيفرة عبر إدارة التعليقات المعالجة واقتراح رسائل الالتزام والتحقق بأدوات shell.
  • إطلاق مساحة Sentry في تطبيق Copilot لتحليل الأعطال وتحضير إصلاحات وطلبات سحب.
  • توفير مقاييس استخدام نافذة Agents ودعم Dev Containers وإنشاء طلبات السحب من داخلها.
  • إتاحة طلب ميزانية Copilot إضافية، واقتراح قيم للخصائص المخصصة، وتنظيف الجلسات غير النشطة اختيارياً.

اختيار نماذج Copilot وفق الأولوية

أضافت GitHub إلى اختيار النماذج التلقائي في Copilot ثلاثة مستويات جديدة هي الكفاءة والتوازن والذكاء. وتتيح هذه المستويات للمستخدم تحديد الطريقة التي يوازن بها Copilot بين الكلفة وجودة النتائج وسرعة الاستجابة، بدلاً من التعامل مع اختيار النموذج كإعداد واحد ثابت. وتؤكد الشركة أن المستويات الثلاثة تختار من مجموعة النماذج المتاحة نفسها، بينما يختلف أسلوب المفاضلة بينها.

بدأ طرح هذه الإمكانية تدريجياً في Visual Studio Code وCopilot CLI وتطبيق Copilot. ويمنح التحديث المستخدمين طريقة أوضح لتحديد أولوية الاستخدام بحسب طبيعة المهمة؛ فالمستوى المختار يعبّر عن التفضيل المطلوب بين تقليل الكلفة، أو الحفاظ على توازن عملي، أو إعطاء الأولوية لجودة الاستجابة. ولا يشير الإعلان إلى إضافة نماذج جديدة بحد ذاتها، بل إلى طريقة جديدة لاختيارها تلقائياً.

مراجعة شيفرة أكثر ارتباطاً بسير العمل

حسّنت GitHub سلوك مراجعة الشيفرة في Copilot بحيث تُحل التعليقات التي عالجها المطوّر تلقائياً خلال المراجعات اللاحقة، مع إبقاء الملاحظات التي لم تُعالج مفتوحة. ويهدف هذا التغيير إلى فصل الملاحظات المنجزة عن التعليقات التي ما زالت تحتاج إلى متابعة، بما يجعل نتيجة المراجعة اللاحقة أكثر وضوحاً.

وعند تطبيق اقتراحات Copilot البرمجية، يستطيع النظام الآن اقتراح رسائل للالتزام بالتغييرات. كما يمكن للمراجعات استخدام أدوات shell للتحقق من التعديلات، في حين تجمع مراجعات Lite النتائج الصادرة عن وكلاء متعددين. وتجمع هذه التحديثات بين تحليل الشيفرة وتحقق عملي من التغييرات، مع إبقاء القرار النهائي بشأن اعتمادها لدى فريق التطوير.

مقاييس الاستخدام وإمكانات الإدارة

أصبحت مقاييس الاستخدام متاحة عموماً في نافذة Agents المخصصة داخل Visual Studio Code. وتعرض تقارير المؤسسات والمنظمات بيانات مثل عدد المستخدمين النشطين يومياً، وعدد الجلسات، وإجمالي رسائل المستخدمين، إلى جانب بيانات النشاط على مستوى المستخدم. وتوضح GitHub أن هذه المقاييس منفصلة عن المقاييس الخاصة بنافذة المحرر، ما يتيح متابعة نشاط الوكلاء في مساحة مستقلة.

وفي المعاينة العامة، يمكن لـCopilot مساعدة مسؤولي المستودعات في اختيار القيم المسموح بها للخصائص المخصصة. فعند إنشاء خاصية تشير مثلاً إلى ما إذا كان المستودع متاحاً عبر الإنترنت، قد يقترح Copilot القيمتين نعم ولا. ويستطيع مالكو المنظمات والمؤسسات تفعيل هذه الاقتراحات أو إيقافها عبر سياسة Copilot.

كما أصبح بإمكان مستخدم Copilot طلب ميزانية أعلى من منظمته أو مؤسسته عند بلوغ حد أرصدة الذكاء الاصطناعي. ويمكن للمالكين ومديري الفوترة الموافقة على الطلب أو تعديله أو رفضه من الإعدادات، وتعيد الموافقة الوصول إلى الأرصدة. تتوفر هذه الميزة عموماً لخطتي Copilot Business وCopilot Enterprise مع الفوترة القائمة على الاستخدام، لكنها غير متاحة للمؤسسات التي تستخدم مستخدمين مُدارين.

من تقارير Sentry إلى إصلاحات قابلة للمراجعة

قدمت GitHub مساحة Sentry الجديدة داخل تطبيق GitHub Copilot لمساعدة الفرق على الانتقال من تقرير العطل إلى إصلاح برمجي مقترح. ومن خلال هذه المساحة، يستطيع المطوّر مراجعة الأخطاء ومكدسات الاستدعاء والسياق المرتبط بها، ثم العمل مع Copilot للتحقيق في السبب المحتمل والتحقق من الإصلاح وإعداد طلب سحب.

يضع التكامل تقارير الأعطال الإنتاجية ضمن مسار عمل واحد يجمع المعلومات التشخيصية والمساعدة البرمجية. ومع ذلك، يظل الإعلان يصف الوظيفة باعتبارها وسيلة للتحقيق والتحقق والتحضير لطلب السحب، لا باعتبارها اعتماداً تلقائياً للإصلاح أو ضماناً بأن كل عطل سيُحل من دون مراجعة بشرية.

وكلاء محليون وإدارة دورة الجلسات

بدأت GitHub طرح دعم تشغيل الوكلاء باستخدام أدوات المشروع وتبعياته داخل Dev Containers المحلية في نافذة Agents. ويتطلب ذلك تثبيت Docker وامتلاك إعداد Dev Container مدعوماً، كما أن الدعم يتوسع تدريجياً. ويتيح هذا المسار تشغيل الوكيل ضمن بيئة أقرب إلى بيئة المشروع الفعلية، مع الاعتماد على الأدوات والتبعيات المحددة في إعداد الحاوية.

وتتيح نافذة Agents أيضاً إنشاء طلبات سحب من جلسات Agent Host من دون مغادرتها. يمكن للمستخدم مراجعة العنوان والوصف اللذين جرى توليدهما، وتحديد ما إذا كان الطلب مسودة، ثم إنشاؤه مباشرة أو تكليف الوكيل بتنفيذه. كذلك يمكن وضع الجلسات غير النشطة في حالة Done تلقائياً بعد دمج جميع طلبات السحب التابعة لها، مع خيار حذفها بعد فترة سماح منفصلة. وهذه الوظيفة اختيارية ومتاحة حالياً في المعاينة.
